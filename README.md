**[הורדת EXE לגרסה 1.0.0](https://github.com/moshiach770chabad749-hue/win11-assistant-bridge/releases/download/v1.0.0/Win11Updater-1.0.0.exe)** · **[כל ההורדות והגיבובים](https://github.com/moshiach770chabad749-hue/win11-assistant-bridge/releases/latest)** · [הוראות הפעלה](docs/QUICKSTART.he.txt)

נדרש Windows 11 x64 וחיבור אינטרנט להורדות Microsoft. חלק מהמחשבים הלא נתמכים עשויים להשלים שדרוג בעזרת הכלי, אך אין הבטחה להצלחה בכל מחשב. ה־EXE של הפרויקט אינו חתום בתעודת מפיץ; אשף Microsoft נבדק בנפרד לפני שימוש. גבה מידע חשוב לפני שדרוג.

קובץ ההפעלה להפצה: `release\1.0.0\Win11Updater-1.0.0.exe`. להפעלה נדרש רק קובץ זה. [הוראות קצרות למשתמש](docs/QUICKSTART.he.txt).

גרסה 1.0.0 אורזת את מסלול העדכון הקיים לגרסת הפצה, ללא שינוי של עקיפות הזכאות או של ברירות המחדל שלהן. נשמרו ניסיונות הורדה חוזרים, שימוש בעותק חתום קיים, בחירת אשף מקומי, בדיקת אינטרנט, גיבוי ושחזור וייצוא יומן ל־ZIP. [פרטי גרסת ההפצה והבדיקות](docs/RELEASE-1.0.0.he.md).

**סטטוס הבנייה הנוכחית:** גרסה 1.0.0 נבנתה והופעלה כאן, ו־30 בדיקות עברו. הורדת האשף ממיקרוסופט ואימותו ושימוש חוזר בעותק חתום נבדקו בפועל גם בגרסה זו. לא בוצע שדרוג מערכת על ידי הסוכן. לא שונתה מדיניות אבטחה כדי להריץ את הכלי. קובץ ההפעלה עדיין אינו חתום בתעודת מפיץ, ולכן מחשבים אחרים עשויים לחסום אותו לפי מדיניותם.

זהו כלי עובד להכנה ולהפעלת **Windows 11 Installation Assistant המקורי של Microsoft** מתוך Windows 11 x64. קובץ אחד להפעלה, עם ממשק עברי ובקשת UAC רגילה. האשף המקורי הוא שמוריד את מערכת ההפעלה ומבצע את השדרוג במקום. הכלי אינו מוריד ISO, יוצר USB, מחליף מתקין או משנה את קובצי Microsoft.

**גבולות האימות:** המשתמש אישר שההתקנה במחשב הלא נתמך הסתיימה ושנכנס ל־Windows המעודכן. זו הצלחה שדווחה על ידי המשתמש במחשב הבדיקה שלו; גרסת הכלי המדויקת ובילד היעד לא נמסרו. אין כאן אימות עצמאי של אותו שדרוג או הוכחה להצלחה בכל מחשב לא נתמך. בבדיקות המקוריות נבדק גם Registry בענף HKCU מבודד. חתימת Microsoft של האשף נבדקת בנפרד מהחתימה של קובץ הכלי.

## הפעלה

1. גבה את הקבצים החשובים ושמור עבודה פתוחה. במחשב נייד חבר לחשמל.
2. הפעל בלחיצה כפולה את `Win11Updater-1.0.0.exe` ואשר את בקשת המנהל של Windows. הפעלה רגילה שומרת את זהות המשתמש המקורי לפני מעבר לחשבון מנהל אחר.
3. סמן את אישורי הגיבוי והחומרה הלא נתמכת. אפשר להשאיר את האפשרויות הניסיוניות כבויות בניסיון ראשון.
4. השאר מסומן **„השתמש באשף שכבר הורד…”** ולחץ **„1. הורדה והכנה”**. אם קיים עותק בן עד 24 שעות, חתימתו נבדקת מחדש ומשתמשים בו. אחרת מורידים מ־Microsoft עם עד שלושה ניסיונות בכשל רשת זמני. רק לאחר אימות חתימה מגבים ומשנים את הגדרות הזכאות. בשלב זה האשף אינו מופעל ואין בקשה לאתחול. שימוש בעותק קיים אינו מבטיח שהוא הגרסה האחרונה; אפשר לבטל את הסימון כדי לבקש הורדה חדשה.
5. להפעלת האשף יש לסמן בנפרד אישור להתקנה ולאתחולים בהמשך, ללחוץ **„2. הפעלת אשף Microsoft”** ולאשר שוב את ההודעה. ללא הסכמה זו הכלי אינו מפעיל את האשף. מרגע ההפעלה **האשף עשוי לאתחל את המחשב בהמשך**; אין כאן הבטחה להשהיית האתחול עד לקבלת אישור נוסף.
6. עקוב אחר חלון Microsoft, קרא ואשר את תנאי הרישיון שלו. המסלול מיועד לשדרוג ששומר קבצים ויישומים. אם מוצעת מחיקה או ששמירת היישומים אינה זמינה, בטל את האשף.
7. לאחר שההתקנה הסתיימה, או לאחר שביטלת וסגרת את האשף, פתח שוב את הכלי ולחץ **„שחזור הגדרות”**. אין לשחזר בזמן התקנה פעילה או כשממתינים להשלמתה.

אם ניסיון קודם הופסק: השאר את הכלי פתוח לדקה ללא מתקינים. כאשר ידוע שההתקנה הקודמת הסתיימה או בוטלה, ניתן לסמן שוב אישור התקנה ואתחולים וללחוץ **„2. ניסיון נוסף באשף”**. הגיבוי המקורי נשמר. האשף המקורי מחליט אם להשתמש בקבצים החלקיים או להוריד מחדש — אין הבטחה להמשך מאותו אחוז. כדי לשנות סימונים לפני ניסיון אחר, יש לשחזר קודם. מטמוני תאימות ש־Windows בנה מחדש נשארים ללא מחיקה; שינוי בערך עקיפה מחייב שחזור והכנה מחדש.

אם מופיע כשל DNS: לחץ **„בדיקת אינטרנט”**. הבדיקה קוראת DNS לשני שרתי Microsoft ומבצעת בקשת HTTPS מסוג HEAD, ללא שינוי רשת. אפשר גם ללחוץ **„בחירת אשף מקומי”** ולבחור את Windows11InstallationAssistant.exe המקורי שהורד מהאתר הרשמי במחשב עם חיבור תקין. הקובץ מועתק ומתקבל רק אחרי אימות חתימה וזהות Microsoft. **זו אינה התקנה ללא אינטרנט:** הורדת מערכת ההפעלה ואימותי תעודות עשויים עדיין לדרוש רשת תקינה. קובץ שנבחר אינו מופעל לפני האישורים הרגילים.

בזמן ההורדה העצמית אפשר ללחוץ **„ביטול הורדה”**. הפעולה אינה הורגת את אשף Microsoft ואינה מבטלת התקנת Windows. אם התחיל אימות חתימה, ממתינים לסיומו לפני הביטול. פס ההתקדמות בכלי מתייחס להורדת האשף הקטן בלבד; האחוזים של הורדת Windows ושל התקנתו מוצגים בחלון Microsoft.

סגירת כלי ההכנה אינה מבטלת את אשף Microsoft. הגדרות ההכנה נשארות עד לשחזור מפורש כדי שלא לבטל אותן באמצע השדרוג. גיבוי ההגדרות אינו גיבוי של Windows, של יישומים או של קבצים אישיים, והשחזור אינו מחזיר גרסת Windows קודמת.

## מה ממומש

- `HwReqChkVars` כ־`REG_MULTI_SZ`: דיווח מטמון על TPM 2, RAM של 8192MB ויכולת/הפעלת Secure Boot; ערכים אחרים נשמרים במיזוג.
- `AllowUpgradesWithUnsupportedTPMOrCPU=1` ב־`HKLM\SYSTEM\Setup\MoSetup`. ערך זה אינו מבטיח שה־Assistant או בדיקה מאוחרת ישתמשו בו.
- `UpgradeEligibility=1` רק בענפי המשתמש המקורי והחשבון המוגבה, לפי SID. אין שינוי לכל החשבונות או לפרופיל ברירת המחדל.
- ניקוי אופציונלי ומגובה של ערכי מטמון בתוך `CompatMarkers`,‏ `Shared` ו־`TargetVersionUpgradeExperienceIndicators`. מפתחות קיימים ו־ACL שלהם נשארים במקום.
- אפשרות ניסיונית לשלושת ערכי `LabConfig`:‏ `BypassTPMCheck`,‏ `BypassSecureBootCheck`,‏ `BypassRAMCheck`.
- אפשרות ניסיונית ל־`/SkipCompatCheck`, שנמצא במחרוזות האשף שנבדק. ברירת המחדל היא הפעלה אינטראקטיבית ללא ארגומנטים.

פרטי הבסיס והגבולות של כל עקיפה ב־[מסמך המחקר](docs/RESEARCH.he.md). ההגדרות אינן מפעילות TPM או Secure Boot בפועל, אינן משנות BIOS ואינן מוסיפות זיכרון או הוראות מעבד.

## גיבוי, יומן והתאוששות

הכלי שומר ב־`%ProgramData%\Win11AssistantBridge`:

| קובץ | מטרה |
|---|---|
| `operations.log` | שלבים, זמנים, שגיאות, נתיבי שינוי, חתימה ותהליכי התקנה שנצפו |
| `backup-<id>.json` | העתק של התוכנית ושל הערכים המקוריים לפני שינוי ראשון |
| `state.json` | אותו מידע עם מצב הפעולה העדכני; מאפשר לפתוח שוב ולשחזר |
| `state.json.prev` | הדור הקודם של יומן המצב |
| `archive-*.json` | פעולות קודמות ששוחזרו |
| `evidence-*` | קטעי יומני Microsoft ומפתח מקורות וזמני שינוי |
| `connection-check.txt` | תוצאת בדיקת DNS/HTTPS האחרונה |

המידע מוגן בהרשאות מנהלים ו־SYSTEM. הגיבוי כולל סוג נתון, תוכן, היעדר ערך, ומפתחות שנוצרו. הכתיבה לדיסק מתבצעת לפני שינוי Registry ראשון. בעת שחזור, ערך שגורם אחר שינה בינתיים לא נדרס; מתקבל **שחזור חלקי** עם פירוט ביומן. מפתחות שהכלי יצר מוסרים רק אם נשארו ריקים. זהו מנגנון פיצוי מגובה, לא טרנזקציה אטומית מול Windows או מול כל כותב אחר ל־Registry.

לאחר קריסה פתח שוב את הכלי: גיבוי פעיל מונע הכנה חדשה מעליו. אם `state.json` אינו ניתן לקריאה, הכלי נעצר; שמור את כל התיקייה. מנהל שמבין את מצבי ההתקנה יכול לשחזר עותק JSON תקין מאותה פעולה מתוך `.prev` או `backup-<id>.json` אל `state.json`, רק כשאין התקנה פעילה. אין להמציא ערכים ידנית או להשתמש בגיבוי ממחשב אחר. ודא שזה אותו `Id` ואותם SIDs. גיבוי מלפני ההפעלה אינו יודע אם האשף כבר התחיל; יש לבדוק זאת חיצונית לפני שחזור.

קיים Mutex גלובלי בין הפעלות הכלי, נעילת קובץ, וזיהוי שמות תהליכי שדרוג לפני הכנה/הפעלה/שחזור. נוסף גם חיווי `SystemSetupInProgress` של Windows: אם הוא פעיל הפעולה נחסמת, ללא שינוי הדגל. סמני CBS/Windows Update לאתחול ממתין מוצגים כאזהרה לפני הפעלת אשף. זיהוי תהליכים אינו הוכחה שכל שירותי ההתקנה חדלו לפעול. אחרי הפעלת אשף נדרשת דקה ללא תהליך מוכר ואישור אנושי לפני ניסיון נוסף או שחזור. אין ניסיון להרוג מתקין או להפסיק התקנה באמצע.

## גבולות חומרה ושדרוג

הכלי חוסם מחשב שאינו Windows 11 x64 Client, מעבד ללא SSE4.2 או POPCNT, בדיקת מעבד שנכשלה, או פחות מ־9GiB פנויים בכונן המערכת. 9GiB הוא סף הכנה שמרני המבוסס על מינימום ההורדה שמיקרוסופט מפרסמת; אינו מבטיח מספיק מקום להתקנה ולחזרה אחורה. מתחת ל־30GiB פנויים או 4GiB RAM מוצגת אזהרה.

הוראות המעבד נבדקות עם CPUID מקומי לשני ביטים נפרדים. הקוד הקטן מבוצע בזיכרון משתמש לקריאה בלבד ואז משוחרר. מדיניות שאוסרת קוד דינמי עלולה לחסום את הבדיקה; במקרה כזה ההפעלה נעצרת. אין שינוי בקרנל או אמולציה של הוראות חסרות. הבדיקה אינה רשימה מלאה של כל דרישות גרסאות Windows העתידיות.

אין עקיפה לבעיות דרייברים, הצפנה, מהדורה/שפה שאינן מאפשרות שימור יישומים, מקום פיזי חסר, דרישות CPU שלא ממומשות בחומרה, או חסימות תאימות אחרות של האשף. עדכון עתידי של Microsoft יכול לשנות את הבדיקות. הימצאות הגדרות ב־Registry אינה מאשרת שמחשב יוכל להשלים שדרוג או לעבוד כראוי אחריו.

## בנייה

נדרש Windows x64 עם .NET Framework 4.8 ומעלה. אין צורך ב־.NET SDK, בחבילות NuGet או בחיבור רשת לבנייה. הסקריפט משתמש במהדר C# המובנה של .NET Framework:

```powershell
.\build.ps1 -RunTests
```

לאריזת גרסה שנבנתה ונבדקה באותה תיקייה:

```powershell
.\package-release.ps1 -UseExistingBuild
```

או הפעל `package-release.ps1` ללא הפרמטר כדי לבנות, לבדוק ולארוז ברצף. האריזה מאמתת את SHA256 של קובץ ההפעלה ושל דוח הבדיקות מול `dist/build-verification.json`. מתקבלים EXE יחיד להפעלה, מקור ב־ZIP, הוראות, רישיון, מניפסט הפצה וקובץ SHA256. אין באריזה קובצי Microsoft או יומנים אישיים ממחשב הבדיקה.

אם מדיניות הארגון מונעת הפעלת PowerShell, יש לפעול לפי המדיניות ולא לשנות אותה אוטומטית. את אותה בנייה אפשר לבצע גם מתוך Developer Command Prompt:

```bat
if not exist dist mkdir dist
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /platform:x64 /optimize+ /warnaserror+ /codepage:65001 /out:dist\Win11AssistantBridge.exe /win32manifest:src\app.manifest /reference:System.Windows.Forms.dll /reference:System.Drawing.dll /reference:System.Runtime.Serialization.dll /reference:System.Net.Http.dll /reference:System.IO.Compression.dll /reference:System.IO.Compression.FileSystem.dll src\*.cs
```

להפעלה דרוש רק ה־EXE מתוך `release/1.0.0`; אין להפיץ את עותק האשף שב־`research` או `tests`. ניתן להוריד אשף חדש או להשתמש במטמון בהתאם לבחירה. יש לפרסם עם הכלי את מגבלותיו והוראות ההפעלה. תעודת חתימה של מפיץ לא סופקה כאן; אין חתימה עצמית שמתחזה ל־Microsoft ואין בקשה לבטל הגנות Windows. אם מוסיפים חתימה אחרי האריזה, צריך לחשב מחדש את המניפסט והגיבובים של הקובץ החתום.

## בדיקות ומצבי פיתוח

[תוצאות וגבולות האימות](docs/TESTING.he.md). כל המצבים הבאים מסתיימים ללא הפעלת מתקין וללא שינוי הגדרות זכאות:

```powershell
# בדיקות לוגיקה, קבצים, בדיקת חתימה שלילית ו־CPUID
.\dist\Win11AssistantBridge.exe --self-test .\dist\test-results.txt

# בדיקת Registry אמיתית רק בענף בדיקה אקראי של HKCU; הענף מנוקה בסוף
.\dist\Win11AssistantBridge.exe --registry-test .\dist\native-registry-test.txt

# הורדת האשף ואימות בלבד, לתיקיית בדיקה לבחירתך
.\dist\Win11AssistantBridge.exe --download-only .\tests\download

# קבלת אשף באמצעות מדיניות המטמון; אימות חוזר לפני שימוש בעותק טרי
.\dist\Win11AssistantBridge.exe --acquire-only .\tests\download

# בדיקת חיבור לקריאה בלבד; תוצאות בקובץ, ללא שינוי DNS או Proxy
.\dist\Win11AssistantBridge.exe --connection-check .\dist\connection-check.txt

# אימות קובץ; קוד יציאה 0 להצלחה, 1 לכישלון
.\dist\Win11AssistantBridge.exe --verify .\tests\download\Windows11InstallationAssistant.exe .\dist\signature.txt

# בדיקות קריאה בלבד / צילום חלון האפליקציה מחוץ למסך
.\dist\Win11AssistantBridge.exe --probe .\dist\machine-probe.txt
.\dist\Win11AssistantBridge.exe --preview .\dist\preview.png
```

מאחר שזה יישום GUI, מסקריפט יש להפעיל באמצעות `Start-Process -Wait -PassThru` כדי להמתין ולקרוא את קוד היציאה. אף מצב פיתוח אינו עוקף את דרישת האישור להתקנה. אין מצב שדרוג שקט.

## כשיש חסימה

שמור את הנוסח המדויק בחלון Microsoft ואת השלב שבו הופיע. לחץ **„שמירת יומן ל־ZIP”** ובחר איפה לשמור. נאספים גם SetupDiagResults.xml אם הוא קיים, יומן הכלי ותוצאת בדיקת החיבור. הקובץ `index.txt` בתיקיית הראיות מציין נתיבי מקור, זמן איסוף, זמני שינוי, מזהה פעולה ותהליכים שנצפו. נשמרים לכל היותר 2MiB מסוף כל קובץ, ועד 12 קבצים מכל תיקיית מקור מוכרת. קובצי תאימות מקוצרים עלולים לא להיות XML תקין. קבצים ישנים אינם ראיה לחסימה הנוכחית. ראיות עשויות להכיל שמות משתמשים, יישומים ונתיבים פרטיים; הן נשמרות מקומית ואינן נשלחות לשום שירות.

במקרה של בדיקה חיה נוספת אין כאן פתרון מאומת לכל החומרה. התוצר נשאר כלי הכנה והפעלה ממשי, עם יכולת לאסוף את הראיות הדרושות להמשך פיתוח. הוא לא מציג „הצלחה” על סמך פתיחת האשף, קוד יציאה או היעלמות תהליך.

## English overview

Free, MIT-licensed Hebrew Windows 11 x64 launcher for the original Microsoft Windows 11 Installation Assistant. It downloads and verifies Microsoft's signed assistant, backs up and applies selected local eligibility settings, and lets the original interactive assistant perform the upgrade. It does not bundle Microsoft binaries, download an ISO, create installation media or replace Windows Setup. Unsupported hardware success is device-dependent; missing CPU instructions cannot be added by registry changes. The launcher itself is unsigned. Read the Hebrew instructions and keep a separate backup of important files before use.

Build on Windows with `.\build.ps1 -RunTests`. No NuGet packages or .NET SDK are required. Automated component tests do not establish that an OS upgrade succeeds on a particular computer. See [release validation](docs/RELEASE-1.0.0.he.md) for the exact verification scope.
