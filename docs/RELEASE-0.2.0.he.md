# גרסה 0.2.0 — הורדה והתאוששות מהפסקה, 25.10.2026

## מה הלוג מוכיח

במחשב הבדיקה המרוחק הותקנה Windows 11 ‏25H2, בילד 26200.9168, עם 15.8GiB RAM וכ־355.6GiB פנויים. הניסיון ב־16:12:06 נכשל בזמן בקשה ל־`go.microsoft.com` עם `WebExceptionStatus.NameResolutionFailure`: המחשב לא פתר את שם השרת. הקריאה הייתה לפני תכנון וכתיבת ערכי זכאות חדשים ולפני הפעלת המתקין באותו ניסיון. זו ראיה לכשל DNS בניסיון החוזר, לא להסבר ההאטה הקודמת.

המשתמש דיווח שבניסיון הקודם הושלמה ההורדה וההאטה סביב 70% הייתה בחלון Microsoft בשלב ההתקנה, ללא הודעת שגיאה ידועה. לא נמסרו יומני Panther/SetupDiag מאותו ניסיון, ולא נמדד זמן שהייה באותו אחוז. לכן אי אפשר להכריע כאן בין עבודה איטית לבין תקלה, או לקשור את ההאטה לאחת מעקיפות הזכאות. [Microsoft מתעדת את יומני השדרוג לפי שלב](https://learn.microsoft.com/en-us/windows/deployment/upgrade/log-files); [SetupDiag עשוי ליצור תוצאת ניתוח אוטומטית](https://learn.microsoft.com/en-us/windows/deployment/upgrade/setupdiag).

בהמשך נמסר קטע נוסף: אימות חתימה והשלמת הכנה ב־16:24, הפעלת האשף עם `/SkipCompatCheck` ב־16:24:16, ומעבר לתהליכי `setupprep` ו־`setup` ב־16:28:41. זה מראה שהניסיון הזה הגיע למנוע ההתקנה של Microsoft. אין בקטע שגיאת התקנה או מדידת השתהות, ולכן הוא אינו מאבחן את ה־70%. שורות `APPLIED ... BlockedBy...` של הגרסה הקודמת מתייחסות לניקוי ערכי מטמון כפי שמוגדר בתוכנית השינויים; הן אינן מציגות ערכים מקוריים ואינן מוכיחות שכל חסימות החומרה הרשומות התקיימו. אין להפסיק מתקין פעיל רק מפני ששמות אלה הופיעו ביומן הכלי.

## שינויים

- עד שלושה ניסיונות הורדה בשגיאות DNS/רשת זמניות, timeout, ‏HTTP 408/429 ו־5xx, עם השהיות של 2 ו־5 שניות. שגיאת חתימה, redirect לא מאושר או שגיאת TLS trust אינן מקבלות הקלת אבטחה.
- הורדה לקובץ ביניים; החלפת עותק קודם מתבצעת אטומית רק אחרי הורדה מלאה ואימות Microsoft. כישלון אינו מוחק עותק קודם תקין.
- מטמון של האשף בלבד. אם נבחר שימוש במטמון וקיים עותק בן עד 24 שעות, הוא מאומת מחדש לפני שימוש. עותק ישן יותר מוצע רק אחרי כשל רשת זמני ואישור מפורש, עם אימות חוזר נוסף. זמן הקובץ אינו הוכחה שהוא האשף האחרון. אפשר לבטל שימוש במטמון ולבקש הורדה חדשה.
- בחירת קובץ מקומי של Installation Assistant המקורי. אין תמיכה ב־ISO, מתקין אחר או קובץ ללא חתימת Microsoft וזהות הקובץ הצפויה. הקובץ המיובא אינו מופעל אוטומטית.
- בדיקת DNS ו־HTTPS מסוג HEAD לקריאה בלבד, ללא שינוי DNS, ‏Proxy, ‏Firewall או שירותי עדכון.
- ביטול ההורדה של כלי ההכנה לפני כתיבת Registry. ביטול זה אינו הורג מתקין Windows. אימות Authenticode שכבר התחיל אינו ניתן לביטול מיידי; הממשק מסביר שצריך להמתין לסיומו.
- ניסיון נוסף באשף לאחר הפסקה, בלי להחליף את גיבוי ההגדרות המקורי. נשמרת תצפית של דקה ללא מתקינים, בדיקת `SystemSetupInProgress` ואישור אנושי נפרד. לפני ניסיון כזה נשמרות ראיות. אין הבטחה שהאשף ימשיך מאותו אחוז.
- מטמוני תאימות ש־Windows בנה מחדש אחרי הניסיון אינם נמחקים שוב אוטומטית. ערכי עקיפה שנשתנו בינתיים מחייבים שחזור והכנה מחדש. שחזור עדיין שומר שינויים חיצוניים כקונפליקטים.
- קריאת סמני Windows לאתחול ממתין כאזהרה לפני הפעלה. אין אתחול אוטומטי מצד הכלי ואין שינוי ידני של סמני Setup.
- תיעוד קוד היציאה של תהליך האשף הראשוני, תוך ציון מפורש שיציאתו עשויה להיות העברת שליטה ואינה הוכחה להצלחה.
- כפתור ראיות ל־ZIP כולל יומן הכלי, תוצאת בדיקת חיבור ו־SetupDiagResults.xml אם נמצא. שימור הקבצים החלקיים של התקנת Windows; אין ניקוי `$WINDOWS.~BT`, איפוס Windows Update או הריגת תהליכים.
- הפרדה ברורה בממשק: פס ההתקדמות בכלי הוא הורדת האשף הקטן; הורדת Windows ושלבי ההתקנה מוצגים על ידי Microsoft.

## מה נבדק בפועל

בנייה ב־C#/.NET Framework x64 עם warnings as errors, והרצת 29 בדיקות. הבדיקות כוללות את כל בדיקות הגיבוי והשחזור הקודמות, פקדי החלון, DNS מדומה שנכשל פעמיים ואז מצליח, הגבלת ניסיונות, HTTP 503 לעומת 403, redirect מחוץ ל־Microsoft, ביטול בזמן השהיה, שימור עותק קיים, אימות מטמון, אישור מטמון ישן, דחיית TLS trust failure ללא fallback, דחיית ייבוא EXE לא חתום, כללי ניסיון חוזר ויצירת ZIP אטומית.

בדיקות HTTP ומדיניות המטמון מדמות שרתים ואימות חתימה כדי לבדוק את זרימת הכשל באופן דטרמיניסטי. הן אינן מוכיחות אמון בקריפטוגרפיה. בדיקות החתימה השליליות משתמשות גם ב־WinVerifyTrust האמיתי.

בנפרד הורד בפועל אשף Microsoft מהקישור הרשמי באמצעות קוד 0.2.0. אימות החתימה הצליח:

```text
FileVersion: 1.4.19041.7779
Signer: Microsoft Corporation
SHA256: A54D847BC7DA71E7E291BA321C80CF6E2F0345B20E399F11670378912D0DB14A
```

מיד לאחר מכן `--acquire-only` השתמש באותו עותק לאחר אימות חתימתו מחדש, ללא הורדה חוזרת של האשף. יומן: `tests/download-0.2.0/download-test.log`. בדיקת חיבור אמיתית הצליחה כאן לשני השמות והחזירה HTTP 302 עבור קישור ההפניה; דוח: `dist/connection-check-0.2.0.txt`. זו אינה הוכחה לחיבור תקין במחשב המרוחק או לכל שרתי הורדת Windows.

בוצעו רינדור חזותי של חלון הגרסה ובדיקת קריאה של נתוני המחשב המקומי. לא בוצעה הפעלה אינטראקטיבית של UAC, לא הופעל אשף Microsoft, לא נכתבו עקיפות חדשות למחשב המקומי, לא בוצע שדרוג ולא בוצע אתחול. לא שוחזר אצלנו מצב ההתקנה סביב 70%, ולא אומת ניסיון חוזר של מתקין שהופסק בפועל.

גרסה זו רצה כאן ללא שינוי מדיניות אבטחה; חסימת Application Control שתועדה עבור בניית 0.1.1 היא היסטורית ואינה מבטיחה שכל בנייה חדשה או כל מחשב אחר ירשו את ההפעלה. קובץ הכלי עדיין אינו חתום בתעודת מפיץ.

## הנחיה למחשב הבדיקה

1. השתמש ב־0.2.0 במחשב עם 25H2, ולא בתוצאות ה־PREFLIGHT של המחשב המקומי שממנו נכתבה התוכנה.
2. לחץ „בדיקת חיבור”. אם DNS עדיין נכשל, אין להניח שהבעיה נפתרה על ידי שימוש במטמון: להורדת מערכת ההפעלה ואימותי תעודות עדיין יידרש חיבור תקין.
3. לפני ניסיון התקנה נוסף, לחץ „ראיות ל־ZIP” ושמור את החבילה של הניסיון שנעצר ב־70%. הקובץ נשמר מקומית בלבד ויש לבדוק פרטיות לפני שיתוף.
4. אם נמצאה הכנה קיימת, המתן לדקה ללא מתקינים ואשר שההתקנה הקודמת הסתיימה או בוטלה. סמן אישור התקנה ואתחולים ולחץ „2. ניסיון נוסף באשף”. אם אין הכנה קיימת, סמן את האישורים ולחץ תחילה „1. הורדה והכנה”.
5. כאשר אשף Microsoft מתקין, אין להסיק כשל מאחוז בלבד. שלח את קובצי הראיות ואת הודעת השגיאה אם תופיע, כדי לברר את השלב המדויק.
